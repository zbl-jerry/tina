# hosts 配置切换：需求、产品与系统设计

> 对应 issue：[#3 支持 hosts 配置切换（本地 profile + 一键应用）](https://github.com/zbl-jerry/tina/issues/3)
> 上游参考：<https://github.com/oldj/SwitchHosts> @ v5.0.3
> 日期：2026-11-21 · 结论：**MVP 实施** · 功能标识：`hostsProfiles`

## 1. 需求调研

### 1.1 用户与任务

开发和测试人员在本地联调、测试环境、生产环境之间切换域名解析。典型任务（JTBD）：

- “把 `api.example.com` 指到本机，联调后端。”
- “切到测试网关，验证预发环境。”
- “清掉临时解析，确认线上行为。”

当前替代方案是 `sudo vim /etc/hosts` 或安装 SwitchHosts。手工编辑的痛点是：没有备份、容易残留、多套配置无法保存、每次都要输密码。

### 1.2 上游产品事实

- 上游是 Tauri + React 的常驻应用，通过 XPC 特权 helper 写系统 hosts。
- 支持本地/远程配置、分组、启用组合、系统托盘切换、备份/恢复。
- v5.0.3 仍在维护，有完整的端到端测试覆盖（`e2e/system-hosts.spec.ts`）。

完整调研记录见 `claudedocs/feature-research-2026-11-20/01-switchhosts.md`。

### 1.3 MVP 边界

做：本地 profile、启用/停用、排序、一次管理员授权、应用前自动备份、一键恢复、写入前静态校验、菜单面板快速切换。

不做：远程订阅与定时刷新、常驻特权 helper、sudoers 规则、分组/文件夹、语法高亮、查找替换、HTTP API、多用户共享、按网络自动切换。

## 2. 产品设计

### 2.1 信息模型

一条配置（profile）包含：

| 字段 | 说明 |
|---|---|
| 名称 | 用户可读，例如“本地开发”“测试网关” |
| 内容 | hosts 片段，一行一条映射或注释 |
| 启用 | 只有启用的配置会写入系统 hosts |
| 顺序 | 列表顺序即写入顺序，影响主机名重复时的解析优先级 |

启用组合是唯一需要持久化的“选择状态”；配置内容随 Tina 的设置备份一起导出。

### 2.2 主要流程

**创建与编辑**

1. 实用工具 → hosts 配置。
2. 新建配置，命名，输入映射。
3. 编辑器下方实时显示格式错误（行号 + 原因），不合法时“应用”不可用。

**应用**

1. 勾选需要生效的配置。
2. 点“应用”，出现一次系统管理员授权框。
3. Tina 先备份当前 hosts，再把启用的配置写入受管区块。
4. 页面与菜单面板显示“已应用 · N 条生效”。

**恢复**

1. 设置页“恢复”选择最近的备份。
2. 同样先备份当前 hosts，再写回所选备份。
3. 受管区块被移除，之前手工添加的其他行原样保留。

### 2.3 界面入口

- **设置页**：实用工具分类下的独立页面。左侧配置列表，右侧编辑器，底部状态与“应用 / 恢复”。
- **菜单面板**：实用工具区域新增一行，打开面板后可直接勾选配置并应用，显示生效条数。
- **功能中心**：`hostsProfiles` 可安装/卸载；关闭后入口与服务一起消失，配置数据保留。

### 2.4 文案原则

- 明确说明会请求一次管理员授权，且不安装常驻 helper。
- 明确说明只改受管区块，其他 hosts 行不受影响。
- 恢复是“把文件写回备份”，不只是撤掉受管区块。
- 不承诺“绝对不会出错”，只承诺备份与校验。

## 3. 系统设计

### 3.1 写入策略：受管区块而不是整文件覆盖

整文件覆盖有两个问题：会丢掉系统或用户手工写的其他行；主机名重复时难以解释。因此采用带标记的受管区块：

```
# >>> Tina hosts profiles >>>
# === 本地开发 ===
127.0.0.1 api.example.com
# <<< Tina hosts profiles <<<
```

应用时：

1. 读取当前 `/etc/hosts`。
2. 移除旧的受管区块（标记必须成对；不成对则拒绝写入）。
3. 去掉末尾空行后追加新的受管区块。
4. 先备份当前文件，再通过一次授权写入。

这样其他工具或用户手工维护的行保持原样，应用与清除都是幂等的。

### 3.2 权限模型

- 复用 `AdminShell`（`do shell script ... with administrator privileges`），只在“应用/恢复”时弹一次密码框。
- 不安装 XPC helper、不写 sudoers、不留常驻特权进程。
- 临时文件写入用户临时目录，由 root 用 `install -m 0644 -o root -g wheel` 安装到 `/etc/hosts`。
- 写入前必须成功备份；备份失败则不进入授权与写入。

### 3.3 校验

逐行校验，接受：

- 空行；
- 以 `#` 开头的注释；
- `IP 主机名 [主机名…] [# 行内注释]`。

拒绝：

- 非法 IP（IPv4 / IPv6 用 `inet_pton` 校验，IPv6 允许 `%zone`）；
- 缺主机名、主机名字符集非法（只允许 ASCII 字母、数字、`-`、`_`、`.`，且不能以 `-`/`.` 开头或结尾）；
- 控制字符（除制表符）、超长行、超长内容；
- 与受管区块标记相同的注释行，防止破坏区块边界。

校验是纯函数，单测覆盖注入、路径穿越、重定向等尝试：这些字符都无法通过 IP/主机名白名单。

### 3.4 数据与状态

| 数据 | 位置 | 备份导出 |
|---|---|---|
| 配置列表与内容 | `UserDefaults`（`hostsProfilesData`，JSON 字符串） | 是 |
| 面板行可见性 | `UserDefaults`（`panelUtilityHostsProfiles`） | 是 |
| 最近备份目录 | `~/Library/Application Support/<bundle id>/HostsBackups` | 否（机器状态） |
| 最近应用时间 | `UserDefaults`（`hostsProfilesLastAppliedAt`） | 否（机器状态） |

“是否已应用”不依赖保存的状态，而是每次读取 `/etc/hosts`，比较受管区块与当前启用组合生成的区块，避免状态与实际文件漂移。

### 3.5 备份与恢复

- 每次实际写入前把当前 hosts 写入 `HostsBackups/hosts-YYYYMMDD-HHmmss-<reason>.bak`。
- 保留最近 10 份，超过即删除最旧。
- 设置页列出最近备份（时间 + 原因），可恢复任意一份。
- 恢复本身也先备份当前文件，所以恢复也可以再撤销。

### 3.6 失败模式

| 失败 | 行为 |
|---|---|
| 配置校验不通过 | 不弹授权，指出配置名与行号 |
| 读取 hosts 失败 | 报错，不写入 |
| 旧受管区块不成对 | 报错，不写入，建议先手工检查或恢复备份 |
| 备份失败 | 报错，不写入（安全优先） |
| 用户取消授权 | 保持原状，删除临时文件 |
| 写入后校验失败 | 报错，提示可从备份恢复 |

### 3.7 并发与重入

- 服务是串行队列上的状态机，`isWorking` 期间拒绝第二次应用。
- 与 `AdminShell` 的全局授权锁配合，不会叠出第二个密码框。
- 应用/恢复完成后统一回到主线程刷新状态。

## 4. 测试计划

纯函数单测（`Tests/HostsProfilesTests.swift`）：

- 合法行：IPv4、IPv6、带 zone 的 IPv6、多主机名、行内注释、空行、注释。
- 非法输入：错误 IP、缺主机名、非法主机名字符、`>`/`|`/`;`/`$`/反引号/路径穿越、控制字符、超长行、超长内容、保留标记。
- 区块合成：追加、替换旧区块、无区块、零启用配置、结尾空行稳定、CRLF 输入。
- 区块移除：成对、不成对、缺失。
- 有效行计数、签名稳定性。
- 备份文件名排序与保留数量。

集成验证（真机手动步骤）：

1. 新建并启用一个映射，应用 → 确认 `ping`/`dscacheutil -q host` 指向新地址。
2. 在 `/etc/hosts` 手工加一行，再次应用 → 手工行仍在。
3. 禁用全部配置并应用 → 受管区块消失，手工行仍在。
4. 恢复最近备份 → 文件内容与备份一致。
5. 取消管理员授权 → 文件未改变，界面显示未应用。
6. 卸载功能后重装 → 配置与启用状态保留。

## 5. 已知限制

- 修改 hosts 只影响新的解析请求；已缓存的连接需要应用自行重连，Tina 不强制刷新 DNS 缓存。
- 不提供语法高亮与查找替换。
- 不做远程订阅与自动切换网络环境。
- 受管区块之外的 hosts 行不由 Tina 管理，也不随配置切换。
- 管理员授权对话框由 macOS 呈现，Tina 无法自定义其外观。
