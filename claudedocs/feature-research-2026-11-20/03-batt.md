# 限制电池充电上限（如 80%）

> 调研日期 2026-11-20 · 上游 <https://github.com/charlie0129/batt> @ v0.10.0
> 决策：**defer** · 建议标签：`enhancement`

### 问题或动机

长期插电使用 MacBook 的人希望把电量停在 80% 左右以减缓电池老化。macOS 的「优化电池充电」是黑盒，达到 100% 后才会停；系统直到 macOS 26.4 才提供可调的充电上限。开发者/办公用户插电一整天时，没有简单办法设置一个硬上限。

### 期望的解决方案

**MVP**

- 在「能耗与显示」的设置里提供充电上限滑块（如 60–100%），以及「本次充满」按钮。
- 达到上限后停止充电，低于下限才恢复（回差避免反复触发）。
- 只在插电的 Apple Silicon MacBook 上显示；不支持的机型隐藏入口。
- 关闭功能或卸载时恢复系统默认充电行为。

**后续可选**

- 低电量阈值、MagSafe 指示灯跟随、自动校准。

第一版明确不做：断电使用电池、绕过系统充电策略、自动校准、CLI/守护进程联动。

### 功能区域

能耗与显示（Energy and display）

### 开源调研结论

#### 硬约束

| 约束 | 结论 | 依据 |
|---|---|---|
| macOS 15 | pass | 上游在 macOS 15 Sequoia 上标记支持；Tina 14 上功能可用，不需要 15+ API |
| 原生实现 | fail / conditional | 上游是 Go 二进制 + GUI 外壳（`batt-v0.10.0-darwin-arm64.tar.gz`）；Tina 需要重写 SMC 读写与状态机 |
| 上游 Release 体积（若有） | pass | DMG 2.7 MB，CLI tar.gz 3.4 MB |
| 复杂度 | fail | 需要常驻 root 权限（`sudo batt install` 安装 LaunchDaemon）写 SMC、处理睡眠/唤醒、固件差异；属于新的特权子系统 |
| 不重复 | new | Tina 只读电池健康，不控制充电 |

#### 上游产品价值

- JTBD：长期插电时把电量控制在一个对电池友好的区间。
- 频率与痛点：插电办公/开发人群每天受益；痛点中高，但用户感知滞后（电池衰减是长期效应）。
- 替代品：macOS 26.4+ 的原生充电上限（80–100%）、AlDente（付费）、系统「优化电池充电」。
- 可核实信号：README 明确注明 macOS 26.4 之后原生已覆盖大部分需求，`batt` 只在更低版本或需要 80% 以下时仍有价值；这是价值随时间下降的直接证据。

#### Tina 用户增量收益

- 新增能力：在 Tina 内设置并保持充电上限，少装 AlDente。
- 协同：与「系统监控 → 电源」的电池健康读数、菜单栏电量读数同一入口。
- 替代：可少装一个付费 App（但只对 macOS < 26.4 或需要 <80% 的用户成立）。
- 代价：常驻 root 权限 + SMC 写入 + 睡眠/唤醒状态机 + 跨机型固件兼容，维护面大；Tina 现有 FanControlHelper 虽已是特权 helper，但不应为了电量上限扩大它的职责。

#### 成本、风险与 MVP

- 规模：L（SMC 后端探测、状态机、权限安装、机型兼容、睡眠处理）
- Tina 增量体积：代码约 0.5–1 MB，但真正的成本是权限安装器与测试矩阵
- 主要风险：特权常驻服务、写入错误可能影响供电与睡眠、机型/固件差异大
- MVP 边界：即便做，也只覆盖 Apple Silicon + 受支持固件的上限设置，不含断电与校准
- 决策：**defer**——价值随 macOS 26.4 原生功能下降，而成本与风险都落在“新增特权子系统”这一硬约束上；触发条件：出现大量 macOS 14–25 用户明确要求，且 Tina 已具备可安全复用的 SMC 写入通道

| 维度 | 分数（1–5） | 理由 |
