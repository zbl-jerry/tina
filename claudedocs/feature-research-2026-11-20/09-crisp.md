# 显示器预设（分辨率/亮度/开关，一键或快捷键切换）

> 调研日期 2026-11-20 · 上游 <https://github.com/didriksg/Crisp> @ v1.7.1
> 决策：**MVP**（预设；HiDPI 缩放 defer）· 建议标签：`enhancement`

### 问题或动机

Tina 已经能调每台显示器的亮度、音量，并支持额外增亮，但没有“场景”概念。每天在工位和家里切换外接屏时，用户要反复改分辨率、亮度，甚至手动关掉内建屏；笔记本合盖/开盖、插拔显示器后这些设置也不会自动恢复。现在只能逐项手调，或者装 BetterDisplay/Lunar 这类重工具。

### 期望的解决方案

**MVP**

- 新增「显示器预设」：保存当前所有显示器的分辨率、亮度、显示器音量、主显示器选择，命名并绑定一个图标。
- 在菜单面板一键应用；也可绑定全局快捷键，或在显示器连接/断开时自动应用指定预设。
- 应用失败（显示器不支持该分辨率、DDC 无响应）时逐项提示，不静默失败。
- 预设只保存公开 API 能读写的内容；不支持的项在编辑界面隐藏。

**后续可选**

- HiDPI/Retina 缩放（需要私有 CoreDisplay 接口，见下）。
- 虚拟显示器、ICC/HDR、输入源切换、物理断开显示器。

第一版明确不做：虚拟屏、色彩配置、显示器输入切换、物理断电。

### 功能区域

能耗与显示（Energy and display）

### 开源调研结论

#### 硬约束

| 约束 | 结论 | 依据 |
|---|---|---|
| macOS 15 | pass | 上游要求 macOS 14+；14 上预设功能完整，无需门控 |
| 原生实现 | pass | 上游 Swift/SwiftUI，4.9 MB DMG；Tina 已有 DDC 与亮度代码 |
| 上游 Release 体积（若有） | pass | `Crisp.dmg` 4.9 MB |
| 复杂度 | conditional | 预设本身只读/写公开的 CGDisplay 模式与现有 DDC 通道（pass）；HiDPI 缩放依赖私有 CoreDisplay 接口（fail，需降级） |
| 不重复 | enhancement | 亮度、额外增亮、显示器音量已在 Tina；缺预设与分辨率切换 |

#### 上游产品价值

- JTBD：不同桌面/显示器组合之间快速切换显示状态。
- 频率与痛点：每天插拔/合盖的用户高频；逐项调整烦，痛点中高。
- 替代品：BetterDisplay/Lunar（付费且有 Pro 层）、系统自身只记住分辨率、手动调整。
- 可核实信号：Crisp 以“免费替代 BetterDisplay/Lunar”为定位，README 明确列出免费范围；用户迁移诉求明确，但具体数量 unknown。

#### Tina 用户增量收益

- 新增能力：一次点击恢复整套显示状态；插拔自动切换。
- 协同：复用现有 DDC 亮度/音量、显示器列表、菜单面板与快捷键系统。
- 替代：可少装 Lunar/BetterDisplay 的基础功能。
- 代价：写入显示模式本身有风险（黑屏/闪烁），必须有超时回滚。

#### 成本、风险与 MVP

- 规模：M（预设模型 + 模式匹配 + 应用/回滚 + UI + 自动触发）
- Tina 增量体积：约 0.3–0.6 MB
- 主要风险：切换到不支持的模式导致黑屏；DDC 慢导致预设应用超时；多显示器匹配错位
- MVP 边界：只做公开 API 能保证的分辨率/亮度/音量/主显示器；不做 HiDPI、虚拟屏、断电、输入切换
- 决策：**MVP**——预设复用现有显示控制，价值明确；HiDPI 缩放作为后续独立评估（私有 API + L 规模，当前不进入）
