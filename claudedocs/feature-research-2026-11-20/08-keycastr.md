# 录制时显示按键（可选按键浮层）

> 调研日期 2026-11-20 · 上游 <https://github.com/keycastr/keycastr> @ v0.11.1
> 决策：**MVP** · 建议标签：`enhancement`

### 问题或动机

录快捷键教程、review 视频或远程演示时，观众看不到你按了什么：画面上只有结果，没有 `⌘⇧4` 或 `⌃Tab` 这样的过程。Tina 的录屏已经能画出光标轨迹和点击涟漪，但按键只记录了“什么时候在打字”，没有任何按键内容。用户现在只能另外开 KeyCastr 或后期加字幕。

### 期望的解决方案

**MVP**

- 录屏设置里增加「显示按键」开关，默认关闭；开启后只在录制期间显示浮层。
- 浮层显示修饰键与普通键的组合（如 `⌘⇧4`、`⌃Tab`、`↵`），可调位置（四角/跟随光标）、字号、停留时长、主题（深/浅）。
- 浮层内容同时烧录进成片；暂停录制时浮层隐藏。
- 安全检查：系统处于安全输入（Secure Event Input，密码框）时立即停止显示并清空浮层；不把按键写入任何日志或录制元数据。
- 明确提示：开启后需要输入监控权限；未授权时开关置灰并给出跳转。

**后续可选**

- 鼠标点击的可视化样式（Tina 已有基础涟漪）。
- 按键历史面板、按 App 过滤。

第一版明确不做：录制之外的常驻按键浮层、鼠标移动轨迹重绘、按键统计。

### 开源调研结论

#### 硬约束

| 约束 | 结论 | 依据 |
|---|---|---|
| macOS 15 | pass | 上游为原生 ObjC 菜单栏工具；事件 tap + 浮层窗口，无 15+ API |
| 原生实现 | pass | 上游 ObjC，2.5 MB zip；Tina 用 CGEvent tap + AppKit 浮层重写，约 S–M |
| 上游 Release 体积（若有） | pass | `KeyCastr.app.zip` 2.5 MB |
| 复杂度 | conditional | 需要输入监控权限（Tina 现有权限枚举里没有），且必须正确处理 Secure Event Input |
| 不重复 | enhancement | 录屏与光标/点击可视化已存在；按键内容显示是缺口 |

#### 上游产品价值

- JTBD：录屏/演示时让观众看到按键过程。
- 频率与痛点：教程作者、远程 pairing、support 录屏；频率中低，痛点中（观众反复问“你按了什么”）。
- 替代品：KeyCastr、Zoom/腾讯会议自带按键显示、后期字幕。
- 可核实信号：项目长期维护（2026-09 仍在发版），README 专门讨论密码安全，说明真实使用中确有隐私顾虑；用户量 unknown。

#### Tina 用户增量收益

- 新增能力：录屏第一次能表达“怎么按的”，而不只是“结果”。
- 协同：复用录制浮层渲染、合成器、光标可视化与暂停时钟。
- 替代：可少装 KeyCastr，并省掉“录屏 + 另开浮层”的窗口对齐问题。
- 代价：新增输入监控权限的申请与解释；隐私风险需要严格限制。

#### 成本、风险与 MVP

- 规模：M（事件采集 + 按键描述 + 浮层渲染 + 合成 + 权限流程）
- Tina 增量体积：约 0.2–0.4 MB
- 主要风险：按键（尤其密码）被录进视频；权限被拒时的降级；Secure Input 判断不完整
- MVP 边界：只在录制期间、默认关闭、只显示按键组合、Secure Input 时强制隐藏；不做常驻浮层
- 决策：**MVP**——成本可控，且 Tina 已有录制渲染管线；隐私风险用“默认关闭 + Secure Input 拦截 + 不落日志”缓解
