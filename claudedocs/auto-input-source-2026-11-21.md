# 按 App 自动切换输入法：需求、产品与系统设计

> 对应 issue：[#4 按 App 自动切换输入法（含浏览器域名与终端程序规则）](https://github.com/zbl-jerry/tina/issues/4)
> 上游参考：<https://github.com/zbl-jerry/TypeLock> @ v1.0.0
> 日期：2026-11-21 · 结论：**MVP 实施** · 功能标识：`autoInputSource`

## 1. 需求调研

### 1.1 用户与任务

中英混用的用户每天要在同一台 Mac 上反复切换输入法。典型任务（JTBD）：

- “在编辑器里写代码用英文，切到微信要用中文。”
- “浏览器查文档用中文，回到终端跑命令要英文。”
- “刚打开某个 App 时用固定输入法，之后切回来沿用我刚才用的那个。”

系统自带的“自动切换到文稿的输入源”只按 App 记住一个源，不区分“刚启动”和“切回前台”，也不能为同一 App 的不同场景给出不同答案。切错的直接成本是删掉半句话重打。

### 1.2 上游产品事实

- TypeLock 是原生 macOS 输入法管理器，v1.0.0（2026-11-18，MIT），Universal 包 5.6 MB。
- 功能：按 App 的启动/激活两条规则、浏览器域名规则、终端程序规则、光标旁浮标、按输入法分配的全局快捷键、排除列表、JSON 配置备份。
- README 的「Switching Precedence」明确顺序：排除 → 浏览器规则 → 终端规则 → App 启动/激活规则 → 全局启动/激活策略 → 不切换。
- 上游使用 TCA + Tuist，规则与偏好存放于 Application Support 下的 JSON 文件。

完整调研记录见 issue #4 的「开源调研结论」，以及 `claudedocs/feature-research-2026-11-20/`。

### 1.3 MVP 边界

做：

- 每条规则绑定一个 App，分别设置“启动后首次激活”和“之后再次激活”。
- 四种行为：跟随全局默认、固定输入源、记住上次使用的源、不切换。
- 全局默认（同样分两个时机）与“永不切换”排除列表。
- 规则导入/导出为 JSON，方便换机与放进 dotfiles。
- 菜单面板显示当前输入法与一键手动切换。
- 切换只发生在 App 激活之后，绝不监听或拦截键盘。

不做（issue 已明确后置）：

- 浏览器域名规则、终端前台程序规则。
- 光标旁输入法浮标、CJKV 焦点修复、统计。
- 每个输入法的全局快捷键（Tina 的快捷键体系另有入口）。

## 2. 产品设计

### 2.1 信息模型

一条规则（rule）包含：

| 字段 | 说明 |
|---|---|
| App | 以 bundle identifier 为身份，显示名只作缓存 |
| 首次激活 | App 启动后第一次来到前台时的行为 |
| 再次激活 | 之后每次回到前台时的行为 |

四种行为：

| 行为 | 含义 |
|---|---|
| 跟随全局默认 | 只在该 App 的规则里可选，解析到同一时机的全局默认 |
| 固定输入源 | 选中一个当前启用的输入源 |
| 记住上次使用的源 | 使用该 App 上次来前台时最终使用的源 |
| 不切换 | 保持现状 |

全局默认是同样的两个时机，但只能用后三种行为，避免自我引用。“永不切换”列表优先于一切规则。

### 2.2 主要流程

**启用**

1. 设置 → 鼠标与键盘 → 按 App 自动切换输入法。
2. 打开自动切换开关。
3. 设置全局默认的两个时机。

**添加 App 规则**

1. 点“添加 App”，从已安装或正在运行的 App 里选择。
2. 新规则的两种情况默认都是“跟随全局默认”。
3. 分别点开两个下拉菜单，选择行为；选具体输入源时菜单直接列出系统已启用的源。

**排除**

1. 在“永不切换”里添加 App。
2. 被排除的 App 即使有规则也不切换，排除优先。

**换机与 dotfiles**

1. 导出 JSON，得到 `tina-auto-input-source.json`。
2. 把文件放进 dotfiles 或另一台 Mac。
3. 导入前校验文件版本与格式，确认后替换全局默认、排除与规则；上次使用的源不随文件走。

**菜单面板**

- 显示当前输入法的短代码与名称、自动切换是否开启。
- 列出已启用的输入源，点一下立即切换。
- 齿轮进入设置页。

### 2.3 界面入口

- **设置页**：鼠标与键盘分类下的独立页面。
- **菜单面板**：实用工具区域新增一行；功能卸载后入口与服务一起消失。
- **功能中心**：`autoInputSource` 可安装/卸载，规则数据保留。

### 2.4 文案原则

- 明确“切换发生在 App 激活之后，不会在打字过程中抢占”。
- 明确“不拦截键盘，不需要辅助功能权限”。
- 明确安全输入（密码框）期间不切换。
- 明确导入会替换哪些内容、保留哪些内容。

## 3. 系统设计

### 3.1 前台监听而不是键盘钩子

服务只订阅 `NSWorkspace.didActivateApplicationNotification`，在 App 激活后读取当前输入源并按规则选择。没有 CGEvent tap，因此：

- 不需要 Accessibility 权限；
- 不会延迟或吞咽按键；
- 与 Super Key、Command Bar 等已有输入源切换互不阻塞，用户手势始终后发生效。

`IsSecureEventInputEnabled()` 为真时跳过切换。

### 3.2 “首次激活”的定义

- 服务启动时把正在运行的 App 记入 `seenActive`，所以启动 Tina 后第一次切到一个早已运行的 App 算“再次激活”。
- App 启动（`didLaunchApplicationNotification`）或退出时从 `seenActive` 移除；它下一次来到前台就是“首次激活”。
- 该状态只在内存中，属于会话状态，不持久化。

### 3.3 决策顺序

与上游一致：

1. 排除列表。
2. 该 App 的规则（按当前时机取首次/再次）。
3. 规则为“跟随全局默认”时，解析到同一时机的全局默认。
4. 具体输入源若已禁用、或已经是当前源，则不动作。

决策函数是纯函数，见 `AutoInputSourceSupport.decision(...)`。

### 3.4 记住上次使用的源

服务同时监听系统分布式通知 `kTISNotifySelectedKeyboardInputSourceChanged`。任何来源的切换（用户按 ⌃Space、Tina 自己的规则、其他 App）都会把“当前前台 App → 新输入源”写入 `autoInputSourceLastSources`。禁用或删除输入源后，记录会被清理。

该映射是本机使用习惯，不进入设置备份。

### 3.5 数据与状态

| 数据 | 位置 | 备份导出 |
|---|---|---|
| 自动切换开关 | `UserDefaults`（`autoInputSourceEnabled`） | 是 |
| 全局默认、排除、规则 | `UserDefaults`（`autoInputSourceData`，JSON 字符串） | 是 |
| 每个 App 上次使用的源 | `UserDefaults`（`autoInputSourceLastSources`，JSON） | 否（本机习惯） |
| 面板行可见性 | `UserDefaults`（`panelUtilityAutoInputSource`） | 是 |
| 首次激活记忆 | 进程内存 | 否（会话状态） |

### 3.6 JSON 格式

存储与导出的配置共用一种结构：

```json
{
  "format": "tina.auto-input-source",
  "version": 1,
  "global": {
    "firstActivation": { "kind": "noSwitch" },
    "reactivation": { "kind": "fixed", "sourceID": "com.apple.keylayout.US" }
  },
  "excludedBundleIDs": ["com.apple.Terminal"],
  "rules": [
    {
      "bundleID": "com.example.Editor",
      "appName": "Editor",
      "timings": {
        "firstActivation": { "kind": "fixed", "sourceID": "com.apple.keylayout.US" },
        "reactivation": { "kind": "rememberLast" }
      }
    }
  ]
}
```

- 手写 dotfile 可以省略 `format`，缺少时按本功能处理；写了其他值则拒绝导入。
- `version` 高于当前版本时拒绝，而不是半解析。
- 解码后统一清洗：bundle id 白名单（字母、数字、`.`、`-`、`_`）、去重、数量上限（规则与排除各 200）、全局默认不允许 `followGlobal`。

### 3.7 失败模式

| 失败 | 行为 |
|---|---|
| 存储 JSON 损坏 | 读为空配置，界面从零开始，不崩溃 |
| 导入文件不可读 | 提示文件无法识别，不改动当前规则 |
| 导入文件来自更新版本 | 拒绝并提示 |
| 目标输入源已被禁用 | 本次不切换 |
| 当前处于安全输入 | 本次不切换 |
| App 没有 bundle id | 不切换 |
| 找不到 App（规则残留） | 设置页标注“此 App 未安装”，规则保留 |

### 3.8 并发与重入

- 所有 `@Published` 状态与 TIS 调用都在主线程。
- 配置写入先清洗再编码，`storedConfiguration` 与服务观察到的 UserDefaults 值比较，避免自我触发重入。
- 输入源启用列表变化时刷新列表并清理失效的“上次使用”记录。

## 4. 测试计划

纯函数单测（`Tests/AutoInputSourceTests.swift`）：

- 配置与上次使用源的 JSON 往返；缺失/损坏读为空。
- 清洗：bundle id 校验、去重、名称修剪、空名回退、数量上限、全局默认不能跟随自身。
- 决策：排除优先、规则覆盖全局、跟随全局按时机解析、固定源被禁用不切换、已是当前源不重复切换、记住上次、无记录不切换、空 bundle id 不切换。
- 导入：正常文件、无 envelope 的手写 dotfile、格式不符、版本过新、非 JSON。
- 上限与清理。
- 15 种语言文案完整、无 em dash、中文标题已翻译。
- 功能目录、默认值、设置备份包含/排除关系。

已执行的验证：

## 5. 已知限制

- 仅 macOS 的 App 级规则；浏览器域名、终端程序规则不在本版。
- “记住上次使用的源”记录的是该 App 前台期间最后一次生效的源，不区分用户手动切换与自动切换。
- 应用通过 ⌘Tab 快速连续切换时，切换在每次激活后立即发生，不做延迟合并；极快的手速下可能感到输入法跳跃。
- 安全输入期间不切换，密码框关闭后要等下一次 App 激活才重新按规则切换。
- 不提供输入法浮标、统计或每个输入法的全局快捷键。
- 浏览器规则、终端规则、浮标动画留作后续可选。
